# RingMaster AI 自动剪辑算法规格（V0）

> 状态：V0 实现中（2026-08-24）｜双端共用此文档，Kotlin/Swift 各自实现后以 golden test 对齐。
> 双端一致性断言：10 首测试集上选区重叠度 >95%（不要求逐毫秒相等）。

## 术语约定（产品文案/合规）

- 端侧 V0/V1 是**确定性信号处理算法**（启发式智能），产品文案一律用「智能」（智能剪辑/智能找高潮），**不用「AI」**——苹果 App Store 审核要求 AI 描述有据可查，纯算法不可宣称 AI
- 「AI」字样保留给 Phase 6 的云端大模型功能（那时才名副其实），并作为付费增值的专属卖点词

## V0：能量法（副歌/高潮检测）

**设计原则**：V0 不引任何第三方音频分析库（AGPL 风险 + 体积），纯自写数值算法，吃 WaveformExtractor 已有的振幅包络（桶级，约 45ms/桶），零额外解码成本。

### 输入
- `amplitudes: FloatArray` —— 0..1 归一化振幅包络（现有波形数据，4000 桶）
- `durationMs: Long`

### 处理流水

1. **平滑**（抑制瞬态尖峰）：滑动窗口平均，窗口 = `max(1, n/300)` 桶（≈0.15s）。实现为前缀和，O(n)。
2. **基线**：`mean = 全曲平滑均值`；`threshold = 1.5 × mean`。
3. **候选段**：平滑值 > threshold 的连续桶构成段；段间间隔 < 1s 的相邻段**合并**（副歌常被小缺口打断）。
4. **主段选择**：取**时长最长**的段（规格 v1：先按"最长"，若验收命中率不足再切到"能量×时长最大"——见 §验收）。
5. **目标长度裁剪**：铃声目标 30s。
   - 段 > 30s：在段内滑动 30s 窗口，取段内能量和最大者。
   - 段 < 15s：向两侧扩展（允许扩展到平滑值 ≥ 0.7×threshold 的邻域）。
6. **静音边界修正**：起点向前、终点向后找最近"低能量点"（平滑值 < 0.2×mean），避免切在人声/乐器中间；找不到则保持。
7. **输出**：`(startMs, endMs)`，clamp 到 [0, duration]，`end - start ≥ 500ms`。
8. **Fallback**：无任何候选段（整曲安静/异常输入）→ 取能量中位数以上最长连续段；仍无 → 默认 30s（取 1/4 处），并标记 `confident=false`，UI 提示"AI 有点懵，已选一个稳定片段，可手动微调"。

### 复杂度
O(n)，4000 桶毫秒级完成，无需后台线程池。

### V1 方向（后置）
MFCC/色度特征 + 自相似矩阵做重复结构检测（副歌重复 2-4 次是结构特征，比能量更鲁棒）。V1 输入需要 22050Hz 单声道 PCM（含解码），成本显著高于 V0，故后置。

## 验收（真机，10 首多曲风测试集）

- [ ] 人工判定副歌/高潮命中 ≥ 7/10
- [ ] 单次检测 < 10s（实际预期 < 1s）
- [ ] 双端重叠度 >95%
- [ ] Fallback 场景（白噪声/纯静音输入）不崩溃、给出合理默认选区

## 反模式守卫

- 不引 ffmpeg/Essentia/librosa（AGPL/体积）
- 不引入"可配置的多算法路径"——V0/V1 切换用版本号，不是运行时开关
- AI 输出永远是"推荐选区"，用户可微调；不做全自动覆盖用户选区
